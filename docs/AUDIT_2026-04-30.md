## 3. Architecture vs implementation

`ARCHITECTURE.md` is accurate as a description of the parser pipeline.
The pieces called out there (`parsecore` registry, `parserffi` CGO bridge,
`internal/store/dict.go` resolver chain, `internal/eval` harness,
`testdata/parser-eval/...`) all exist and behave as documented.

The `omorfi` parser in `internal/parsecore/parsecore.go` is wired through
the same registry and override-rule shape described in
`docs/OMORFI_ADAPTER.md`. The auto-default `findOmorfiAdapter` matches
`scripts/omorfi_adapter_example.py` and `Makefile`'s `setup-omorfi`.

`internal/store/dict.go` matches the README's resolver-chain documentation
exactly: direct dict → Finnish possessive strip → compound split →
case-suffix strip. The compound splitter has the two-pass strategy
(`leftLemma == left` then `rightLemma == right`) the comment describes.

The `cards` and `card_state` migration block in `internal/store/db.go`
(`ensureLangScopedCardsTable`) aligns with the global-card model in
`docs/FEATURES.md` and `docs/srs-deck-spec.md`.

## 4. Findings worth fixing now

### 4.1 `make run` (and `go run`/`go test`) require `LD_LIBRARY_PATH`

`README.md` and `Makefile` both promise that `make run` is enough to start
the app on a fresh checkout. In practice the shipped `internal/parserffi`
linkage forced dynamic loading of `libparser.so`:

```
#cgo LDFLAGS: -L${SRCDIR}/../../parser/target/release -lparser -ldl -lm
```

The resulting binary records `NEEDED libparser.so` with no `RUNPATH`, so:

- `./finnestdb` exits immediately with `error while loading shared
  libraries: libparser.so: cannot open shared object file`.
- `go test ./...` in `internal/api`, `internal/eval`, and
  `internal/parsecore` fails the same way.

`parser/Cargo.toml` already builds `cdylib` and `staticlib`, so the fix
is to link the static archive directly. After the change in this PR:

```
#cgo LDFLAGS: ${SRCDIR}/../../parser/target/release/libparser.a -ldl -lm -lpthread
```

`make run` and `go test ./...` now succeed without `LD_LIBRARY_PATH`,
the resulting binary no longer depends on `libparser.so`, and Playwright's
21-test suite continues to pass.

This is the only behavioral fix in this audit PR.

## 5. Findings to track (no code change in this PR)

These are documentation-, scope-, or scaffolding-level gaps. They line up
with items already in `TODO.md`, but it is worth being explicit about
them in one place.

### 5.1 Admin feedback queue UI is a placeholder

`web/index.html` ships an `#admin-feedback-page` that says "No corrections
to review yet" regardless of state. The backend `/api/admin/parse-feedback`
GET/PATCH is implemented; the admin UI is not. PR 5's acceptance criterion
("admin queue surface … with accept / reject / needs follow-up actions")
is not met yet.

### 5.2 Known-words UI is missing

`POST/GET/DELETE /api/known-words` work and are tested
(`internal/api/handlers_test.go`), but `web/app.ts` has no UI surface that
calls them. Per PR 4 in the plan, alpha users are expected to import known
words to bootstrap the deck-creation skip behavior; today they cannot do
that without crafting HTTP requests directly.

### 5.3 Estonian external benchmark slot is missing

`docs/CROSS_LANGUAGE_STRATEGY.md` and PR 7 require an EstNLTK/Vabamorf
adapter slot symmetric to `omorfi` for Finnish. `internal/parsecore`
does not expose one, `cmd/parsertest` does not list one, and
`internal/parserules/estonian.go` is intentionally minimal (case suffixes
only). Today the ET evaluation track only has `basic` vs `custom`.

### 5.4 Make targets do not match the plan

`docs/CROSS_LANGUAGE_STRATEGY.md` and the alpha plan promise three top-
level eval targets:

- `make eval`
- `make compare-parsers` (✅ exists)
- `make eval-check`

Only `compare-parsers` is in `Makefile`. `make eval` and `make eval-check`
are not. This is a docs/build drift, not a code defect.

### 5.5 Several docs are referenced but do not exist

The plan and changelog reference these companion docs as future work:

- `docs/PARSER_FEEDBACK_LOOP.md`
- `docs/EVAL_AND_CI.md`
- `docs/KNOWN_WORDS.md`
- `docs/SYSTEM_OVERVIEW.md`
- `docs/PARSER.md`
- `docs/MICHAEL_TODO.md`
- `docs/SECURITY_REVIEW_ALPHA.md`

`docs/CHANGELOG.md` already labels these as "added in later PRs" so this
is expected, but they are linked from live docs (`FEATURES.md`,
`CROSS_LANGUAGE_STRATEGY.md`, `TODO.md`) without those links being
neutralized yet.

### 5.6 PR-9 hardening hasn't started

There is no rate limiting, no CSRF posture beyond `SameSite=Strict`, and
no security review document. The cookie is `HttpOnly`, `SameSite=Strict`,
and 7-day, but `Secure` is not set, which is fine for local dev and
should be re-evaluated before any non-local deployment.

### 5.7 Parse-session retention story is undecided

`POST /api/parse` stores `source_text` for every authenticated parse with
no purge path (also flagged in `TODO.md` "Post-Alpha Follow-Ups").
`docs/FEATURES.md` is honest with users about this in
"What We Store During Alpha", but there is no user-visible delete control
and no admin TTL job, which is a privacy posture worth tightening before
broader access.

### 5.8 Minor code-level smells

- `internal/parsecore/parsecore.go` — the `omorfiParser` rebuilds two
  resolution maps (`directResolutions`, `customResolutions`) on every
  request via two separate `BatchLookupForms` calls. This is fine for
  the current adapter slot but doubles SQLite traffic vs the
  `dictionaryParser` path. Worth revisiting if Track A starts running
  Omorfi at scale.
- `internal/store/dict.go` `tryCompoundSplit` declares `_ = leftLemma`
  / `_ = leftPOS` in pass 2; intentional but the comment is what
  documents the design choice (use surface left to preserve genitive
  marker). This is fine; flagged so a future cleanup doesn't regress it.
- `internal/store/db.go` `isKnownOrIgnored` uses `COUNT(*)` over a
  `UNION ALL`; `TODO.md` already lists replacing it with `EXISTS`.

## 6. Summary

The product code matches the consumer-alpha plan for slices PR 1–PR 6 in
its backend and surface routing. The visible gaps are concentrated in:

- admin tooling for parse feedback (UI),
- known-words UI,
- Estonian external benchmark and the missing `make eval*` targets,
- Track B reporting,
- the formal security/hardening pass (PR 9),
- and a few docs the plan promises but has not yet shipped.

The one runtime defect found during audit — a binary that can't actually
run on a clean checkout because of dynamic linkage to `libparser.so` —
is fixed by switching `internal/parserffi` to link the static archive
that `parser/Cargo.toml` already produces. With that fix, every
documented build/test/UI command works on a fresh checkout without
extra environment configuration.
