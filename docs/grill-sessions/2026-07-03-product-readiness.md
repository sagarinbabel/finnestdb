Stable product decisions from this grill:

- Public alpha is an anonymous parser demo plus signed-in learner product, with
  open signup. Anonymous users can paste, parse, get a word list, and explore
  it; durable learning requires sign-in.
- First-session success is real text -> useful parse -> next action; activation
  is save/add deck and start review.
- Cold start includes both learner-owned text and a curated embedded text
  catalog. Catalog metadata/text fixtures are checked in and lazy-loaded.
- Catalog target is FI/ET stories, articles, and poems across Easy/Medium/Hard
  with two texts per bucket; difficulty is computed from corpus/parser metrics
  and human sanity-checked.
- Known vocabulary is surface-first. Known surfaces do not automatically imply
  lemmas or other forms. Current lemma-backed persistence is implementation
  debt.
- Alpha review cards are surface-form-in-context cards; homographs become
  sense-aware cards when evidence supports distinct meanings.
- Real FSRS is alpha scope, but narrow: Go runtime, default parameters, current
  buttons, feature flag, migration/fallback, and tests after card identity is
  stabilized.
- Ambiguous known-word imports resolve lazily in context. In parse results,
  **Study this meaning** means "creates a review card when you save."
- Parser confidence means contextual sense-selection confidence, not learner
  knowledge. Add a Finnish-first ambiguity eval slice before simplifying UI.
- Parser feedback needs a flag-only path before low-confidence ambiguity UI can
  ship honestly.
- Accepted parser feedback must not rewrite learning history. Known-faulty
  learner-facing content must be removable from circulation.
- Minimal faulty-content quarantine is a public-alpha gate. Quarantine is global
  after admin confirmation, quiet for learners, excluded from current stats, and
  traceable for admins.
- Alpha quarantine is admin-only. Duplicate/trusted-threshold evidence is
  collected but does not auto-suppress content.
- Alpha issue schema stays small: `parse_feedback` for raw intake plus
  `correction_issues` linked from feedback. Defer rich target/event tables.
- Alpha admin UI uses one feedback/issues queue with filters, simple required
  classification, notes, duplicate counts, and "Quarantine now"; no broad
  in-app data editor and no separate Issues page yet.
- Email verification does not block first value after signup. It can gate
  higher-risk or higher-trust actions later.
- Initial hosted alpha should plan for roughly 1,000 concurrent users, degrade
  gracefully above that, and scale horizontally as funding/server capacity grows.
- Anonymous parsing uses a stricter configurable text-size limit than signed-in
  parsing; signed-in keeps the current 1,500,000-character ceiling.
- Finnish and Estonian launch with equal product status. Audit concrete
  asymmetries; do not label either language experimental or secondary.
- Public alpha launches when core journeys work and every known rough edge is
  classified as non-dangerous under the go-live rubric.
- Launch issues live in `TODO.md`, not a new document. The go-live checklist
  defines the rubric; TODO carries the executable ledger.
- Documentation consolidation happens before implementation handoff. New agents
  should start from `TODO.md` rather than this grill transcript.
- A formal Michael sign-off checklist is skipped for now, but the first
  experience quality bar is high: about 95% of first-run journeys should feel
  excellent before public alpha.
- Minimal telemetry is post-launch roadmap, not a launch blocker if server logs
  plus manual feedback/admin review are available.
- Product name is **FinnEst**. `finnestdb` remains a technical repo/database
  name unless explicitly renamed later.
