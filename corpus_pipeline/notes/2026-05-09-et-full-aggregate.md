## Issues found / fixes queued for the next run

The reviewer surfaced four real concerns that this run dodged but the
next one needs:

1. **P1 — capped-TSV writer overshoots and truncates.** The
   `cappedTSVWriter` estimates row size and `os.File.Truncate`s on
   overshoot — that can cut mid-row. Fix: encode each candidate row
   into a `bytes.Buffer` with `csv.Writer`, measure exact bytes, only
   commit if it fits. No truncation.

2. **P1 — phase 4 still bulk-loads `hashToText`.** At 70M ET sentences
   this map ate ~10 GB of heap and pushed sys to 66 GB (heavy swap).
   Fix: insert `(hash, final_id)` into `tmp_sentence_id`, then stream
   sentences via `SELECT s.text, sid.id FROM tmp_sentences s JOIN
   tmp_sentence_id sid USING (hash) ORDER BY sid.id`. Same JOIN for
   occurrences.

3. **P2 — sentence budget only stops between sources.** The intra-
   source flush in `ingestText` doesn't check `ufSentencesBudget`, so
   a single huge source can keep filling well past the target. Fix:
   inside `flushPara`, also break out and set `budgetSourcePartial`.

4. **P2 — wordlist scratch export is N×SQLite-queries.** The bounded-
   memory phase 4 path I wrote does one indexed SELECT per surface.
   18M surfaces × per-surface SELECT works but is slow. Fix: populate
   a `tmp_surface_order` table from in-memory surface counts, then one
   streaming `SELECT … FROM tmp_wordlist JOIN tmp_surface_order USING
   (surface) ORDER BY o.sort_key` per output.

These four are the deltas before the next ET / FI run.
